# DX推進・業務改善担当を目指す3か月の学習計画

## この計画の前提

- **目標**：3か月後に「自分の業務を1つ改善した事例」を説明できる状態になる。あわせて ITパスポート（ITと経営の基礎を問う国家試験）に合格する
- **時間**：週5時間ほど（平日30分×4日、休日3時間×1日）。仕事と並行して進める想定
- **考え方**：知識より**実践の記録**を優先する。学んだことはすぐ自分の業務で試す

各週のチェックボックスを上から順に潰していく。遅れたら次の週に持ち越してよい。ただし「改善を1つやり切る」ことは削らない。

## 全体の流れ

| 月 | テーマ | 終わったときの状態 |
| --- | --- | --- |
| 1か月目 | 業務を見える化する | 自分の業務の流れを図にし、改善する対象を1つ決めている |
| 2か月目 | ツールで改善する | 決めた業務を、ツールを使って実際に改善している |
| 3か月目 | 定着させて成果をまとめる | 効果を数字で示し、実績として書き上げ、ITパスポートを受けている |

## 1か月目：業務を見える化する

### 第1週：自分の業務を書き出す

- [ ] 1週間分の業務を、30分単位でメモに残す（何を、何で、どれくらいの時間やったか）
- [ ] 繰り返し発生している作業に印を付ける
- [ ] 「面倒」「ミスしやすい」「自分しか分からない」と感じる作業を3つ挙げる
- [ ] ITパスポートの参考書を1冊決める（「ストラテジ系」と呼ばれる経営分野の章から読み始める）

### 第2週：業務フロー図を学ぶ

- [ ] 業務フロー図の基本を学ぶ。BPMN（業務の流れを図にするときの共通ルール）の主要な記号だけ押さえる
- [ ] 第1週で挙げた作業のうち1つを、紙か作図ツール（draw.io、Figma、Miro など）で図にする
- [ ] 図に「誰が」「何を使って」「どこで待ちが発生しているか」を書き込む
- [ ] ITパスポート：ストラテジ系を読み進める

### 第3週：課題を切り分ける

- [ ] 図にした業務の問題点を「時間がかかる」「ミスが起きる」「属人化している」に分類する
- [ ] 各問題について、今どれくらいかかっているかを数字で記録する（例：月に何時間、何回やり直したか）
- [ ] 同僚1人に業務のやり方を聞き、自分の図と違う点を書き足す（ヒアリングの練習）
- [ ] ITパスポート：「マネジメント系」（プロジェクト管理や業務管理の分野）の章を読む

### 第4週：改善する対象を決める

- [ ] 改善する業務を1つに絞る。選ぶ基準は「効果が数字で測れる」「自分の権限で変えられる」「1か月で終わる大きさ」
- [ ] 改善前の状態（かかる時間、手順の数、ミスの回数）を記録して残す
- [ ] 「こうなったら成功」という目標を1文で書く（例：週次報告の作成時間を60分から15分にする）
- [ ] ITパスポートの過去問を1回分解き、苦手な分野を把握する

## 2か月目：ツールで改善する

### 第5週：表計算を整える

- [ ] Googleスプレッドシート（または Excel）で、データを「1行1件、1列1項目」の形で持つ練習をする
- [ ] よく使う関数を押さえる（SUMIFS、COUNTIFS、VLOOKUP または XLOOKUP、IF）
- [ ] ピボットテーブル（データを好きな切り口で集計する機能）を使って、1つ集計表を作る
- [ ] ITパスポート：「テクノロジ系」（ITの技術分野）の章を読み始める

### 第6週：ノーコードツールに触れる

- [ ] ノーコードツール（プログラムを書かずに業務アプリを作れるツール）を1つ選び、無料プランで触る。候補は kintone、Notion
- [ ] 紙や Excel で管理している台帳を1つ、そのツールに移してみる
- [ ] 選んだツールで「できること」「できないこと」をメモにまとめる
- [ ] ITパスポート：テクノロジ系を読み進める（ネットワーク、セキュリティの章を重点的に）

### 第7週：自動化を試す

- [ ] 自動化ツールを1つ選んで触る。候補は Google Apps Script（Googleのサービスを動かせる簡単なプログラム）、Zapier、Power Automate
- [ ] 「AでこうなったらBをする」形の自動化を1つ作る（例：フォームに回答が来たらチャットに通知する）
- [ ] AI（ChatGPT、Claude など）に、自動化の手順やコードの書き方を相談しながら進めてみる
- [ ] ITパスポートの過去問を1回分解く

### 第8週：対象の業務を改善する

- [ ] 第4週で決めた業務に、第5〜7週で覚えた方法を当てはめて改善する
- [ ] 改善後の手順を、自分以外の人が読んでも分かるように書き出す
- [ ] 改善後に起きた問題や、想定外の例外を記録する
- [ ] ITパスポートの受験日を決めて申し込む（3か月目の後半を目安にする）

## 3か月目：定着させて成果をまとめる

### 第9週：効果を測る

- [ ] 改善後の状態を、第4週と同じ項目で記録する
- [ ] 改善前と改善後を並べて比べる（時間、手順の数、ミスの回数）
- [ ] 月や年に換算して、削減できた時間を出す
- [ ] ITパスポート：過去問で間違えた問題を解き直す

### 第10週：他の人に広げる

- [ ] チェンジマネジメント（変化への抵抗を減らしながら新しいやり方を広げる進め方）の基本を学ぶ
- [ ] 改善したやり方を同僚1人に試してもらい、感想を聞く
- [ ] つまずいた点をもとに手順書を直す
- [ ] ITパスポートの過去問を1回分解く

### 第11週：実績としてまとめる

- [ ] 改善の事例を書く。項目は「改善前の課題」「やったこと」「結果（数字）」「次に改善したいこと」
- [ ] 書いた事例を [`portfolio/`](../portfolio/) に1件として残す。書き方は [`portfolio-entry-template.md`](../docs/templates/portfolio-entry-template.md) と [`portfolio/README.md`](../portfolio/README.md) の匿名化の方針に従う
- [ ] ITパスポート：苦手な分野を集中して見直す

### 第12週：受験と振り返り

- [ ] ITパスポートを受験する
- [ ] 3か月を振り返り、「できるようになったこと」「まだ足りないこと」を書く
- [ ] 次の3か月で改善する業務を1つ選ぶ
- [ ] 次に目指す資格を検討する（DX検定、DX推進パスポートなど。上位を目指すなら ITストラテジスト）

## 進め方のコツ

- **完璧を目指さない**：ツールは全部覚えなくてよい。「この業務ならこれが使えそう」と当たりが付けば十分
- **小さく始める**：最初の改善は、自分1人で完結する業務を選ぶ。他の人を巻き込むのは2回目からでよい
- **記録を残す**：改善前の数字を取り忘れると、効果を示せなくなる。第4週の記録は特に大事
- **Webディレクターの経験を使う**：要件定義、関係者の調整、分かりやすい資料作りは、DX推進でそのまま強みになる

## 注意

資格の名前、試験の範囲、申し込み方法は変わることがある。受験の前に公式サイトで最新の情報を確認する。
