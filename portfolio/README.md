## 書くときの方針

**見た目の成果物ではなく、判断とその結果を書く。**

デザイナーやエンジニアと違い、ディレクターの仕事は完成したサイトの中に埋もれて見えない。「きれいなサイトを作りました」では、誰の手柄か読み手に伝わらない。「どういう状況で、何を選び、どうなったか」を書いて初めて実績になる。

数字を1つでも入れる。「使いやすくなった」より「離脱率が42%から28%になった」のほうが、読み手が自分で判断できる。

### 守秘義務への配慮

クライアント名を出せない案件のほうが多い。その場合は匿名化して書く。

- **社名を伏せる**: 「株式会社〇〇」→「食品メーカー（従業員300名規模）」
- **出せる数字と出せない数字を分ける**: 売上額そのものは伏せ、変化率だけ書く
- **迷ったら公開情報の範囲にとどめる**: 公開されているサイトそのもの、プレスリリースに載っている内容なら問題になりにくい

各ファイルの末尾に「掲載可否」の欄がある。確認が取れているかどうかを、その都度メモしておく。**あとから「これ出して良かったんだっけ」と分からなくなるのが一番困る。**

## 新しい実績を書くとき

ファイル名は英小文字とハイフン（例: `food-maker-renewal.md`）。社名を伏せる案件は、ファイル名にも入れない。
