# 日本語の校正

所有者（Webディレクター）の文章を、**意味と書き手らしさを保ったまま**、自然で読みやすい日本語に整える。

書き直しではなく校正である。内容を足したり、主張を変えたり、構成を組み替えたりはしない。それが必要だと思ったら、直さずに「提案」として別に伝える。

## 対象の受け取り方

- ファイルのパスを渡されたら、そのファイルを読む
- 文章を貼り付けられたら、その文章を対象にする
- 何も指定がなければ、どの文章を校正するか聞く

## 校正の強さ

指定がなければ **標準** で行う。

| 強さ | 直すもの |
| --- | --- |
| 軽め | 誤字脱字、変換ミス、表記ゆれ、明らかな文法の誤りだけ |
| 標準 | 軽めに加えて、回りくどい表現、長すぎる文、ねじれた文、読点の位置 |
| しっかり | 標準に加えて、段落内の文の順番、言葉の選び方、冗長な段落の圧縮 |

## 触らないもの

- 記事冒頭の `---` で囲まれた設定部分（title、description などの値の中身は校正してよい）
- URL、ファイル名、コード、HTML のタグやコメント
- 固有名詞（社名、サービス名、人名）の表記。ただし明らかな誤記は指摘する
- 引用部分
- 書き手が意図して使っている口語や言い回し。迷ったら直さずに質問する

## 基準

### 文体

- 文末は「です・ます」でそろえる。ただし箇条書きと表の中は、体言止めや「〜する」でもよい
- 1文はおおむね60字までを目安にする。長い文は2つに分ける
- 主語と述語がねじれている文を直す（例：「この記事の目的は、〜を紹介します」→「この記事では、〜を紹介します」）
- 「〜が、〜が」のように、同じ助詞が1文に続くのを避ける

### 回りくどい表現

| 直す前 | 直した後 |
| --- | --- |
| 〜することができる | 〜できる |
| 〜を行う（例：確認を行う） | 〜する（確認する） |
| 〜という形になります | 〜になります |
| 〜ということになります | 〜です |
| 〜させていただきます | 〜します（相手の許可が要る場面を除く） |
| 〜と思われます | 〜と考えられます、または言い切る |
| 〜的な感じ | 具体的な言葉に置き換える |

### 機械的・定型的な言い回し

読者に「テンプレートで書いた文章」と感じさせる言い回しは避ける。

- 「いかがでしたか？」「〜と言えるでしょう」「〜ではないでしょうか」の多用
- 「〜することが重要です」「〜がポイントです」を何度も繰り返す
- 中身のない前置き（「現代において〜はますます重要になっています」など）
- 毎段落を「まず」「次に」「さらに」でつなぐ

### 表記

このブログでは次の表記にそろえる。

| 使う | 使わない |
| --- | --- |
| Web、Webサイト | ウェブ、ウェブサイト、WEB |
| サイト | ホームページ（「トップページ」の意味で使う場合を除く） |
| ディレクター、Webディレクター | ディレクタ |
| こと、とき、ところ、もの（形式名詞） | 事、時、所、物 |
| できる、ください、すべて、さまざま、いろいろ | 出来る、下さい、全て、様々、色々 |
| および、または、ならびに | 及び、又は、並びに |
| 〜など | 〜等 |
| 数字は半角（3つ、10個、2026年） | 全角数字 |
| 英字は半角 | 全角英字 |
| 括弧は全角（）、かぎ括弧「」 | 半角の ( ) で日本語を囲む |

ここにない語は、文章の中で最初に出てきた表記にそろえる。

### 専門用語

読み手はWeb制作に詳しくない人も想定する。専門用語が説明なしで初めて出てきたら、短い補足を付けることを提案する（例：「DNS（ドメインとサーバーを結び付ける仕組み）」）。補足は勝手に足さず、提案として出す。

## 返し方

次の3つを、この順番で返す。

1. **校正後の文章**：全文。ファイルの場合も、まずは会話の中で示す
2. **直した箇所の一覧**：「直す前 → 直した後 ／ 理由」を箇条書きで。表記ゆれのように同じ理由で何か所も直したものは、1行にまとめて件数を書く
3. **確認したいこと・提案**：意味があいまいで直せなかった箇所、内容に関わる提案（補足の追加、段落の入れ替えなど）

ファイルを書き換えるのは、所有者が「反映して」と言ってから。勝手に上書きしない。

直す箇所がほとんどなければ、無理に直さず「大きな問題はありません」と伝える。
