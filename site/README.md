# site

公開するポートフォリオサイトのファイル。

## 構成

| ファイル | 中身 |
| --- | --- |
| `index.html` | サイト本体。HTMLとCSSを1つにまとめてある |

ページが2枚以上になったら、CSSを別ファイルに切り出す。1枚のうちは分けないほうが編集しやすい。

## 書き換え方

`index.html` の中で、**まだ仮のままの場所**には **`★`** のコメントが付けてある。そこだけ触れば形になる。

| 箇所 | 状態 |
| --- | --- |
| 名前（冒頭とフッターの2か所） | 確定済み。`unchange`（不変） |
| 自己紹介文 | 仮 |
| できること（3つ） | 仮 |
| 実績 | 0件 |
| 連絡先 | 仮 |

屋号は `unchange`。リポジトリ名とドメイン（unchange.jp）に揃えてある。冒頭の見出しには、読みとして「不変」を小さく添えている。

### 実績を1件追加する

`index.html` の「実績」の中に、コメントアウトされたブロックがある。

1. `<!--` と `-->` を消してコメントを外す
2. 中身を書き換える
3. 1件目を追加したら、`<div class="empty">実績を準備中です。</div>` の行を消す

2件目以降は、同じブロックを複製して増やす。新しいものを上に置く。

書く内容の下敷きには [`portfolio/`](../portfolio/) の記事を使う。**先に `portfolio/` に詳しく書き、そこから抜粋してサイトに載せる**という順番にすると、書き直しが減る。

## 公開の仕組み

`main` ブランチの `site/` が更新されると、[`.github/workflows/pages.yml`](../.github/workflows/pages.yml) が動いて GitHub Pages に反映される。手作業でのアップロードは不要。

反映まで1〜2分かかる。進行状況はリポジトリの **Actions** タブで見られる。

### 最初の1回だけ必要な設定

リポジトリの **Settings → Pages** を開き、**Source** を **GitHub Actions** にする。これをしないと公開されない。

## 独自ドメイン（unchange.jp）で公開する

サイトは **https://unchange.jp/** で公開する。ドメインは **お名前.com** で取得済み。

設定はすべてブラウザ上の管理画面で行う。リポジトリのファイルを変える必要はない。上から順に進める。

### 1. ドメインの持ち主であることを GitHub に登録する

他人に unchange.jp を勝手に使われないようにするための手続き。

1. GitHub 右上のアイコン → **Settings** → 左メニューの **Pages** を開く（リポジトリではなく、アカウントの Settings）
2. **Add a domain** に `unchange.jp` を入れる
3. 「`_github-pages-challenge-ssunchange` に、この文字列の TXT レコードを追加して」という指示が出る。画面は開いたままにしておく
4. お名前.com で TXT レコードを追加する（次の手順2の表の最後の行。A レコードなどと一緒に入れてよい）
5. GitHub の画面に戻り **Verify** を押す。反映待ちで失敗したら、時間をおいて押し直す

### 2. お名前.com で DNS を設定する

DNS は「このドメイン名で来た人を、どのサーバーに案内するか」を決める設定。unchange.jp は **お名前.com** で取得しているので、お名前.com の管理画面で行う。画面の文言は時期によって少し変わることがあるので、近い表示を探す。

1. **お名前.com Navi** にログインする。途中で有料オプションの案内が出たら、申し込まずに閉じて進む
2. 上のメニューから **ネームサーバーの設定 → ドメインの DNS 設定** を開く
3. `unchange.jp` を選んで **次へ** を押す
4. 「**DNS レコード設定を利用する**」の **設定する** を押す
5. 下の表の6行を1行ずつ入力し、そのつど **追加** を押す。TTL は初期値のままでよい
6. 一覧に、ホスト名が空欄の A レコードや `www` の行が**もともと入っていたら、削除にチェック**を入れる。古い設定が残っていると、正しく表示されない
7. 画面下のほうの「**DNS レコード設定用ネームサーバー変更確認**」に**チェックを入れる**（理由は下に書く）
8. **確認画面へ進む** → 内容を確かめて **設定する**

ホスト名の欄には、ドメインより前の部分だけを入れる。`.unchange.jp` は自動で付く。

| ホスト名 | TYPE | VALUE |
| --- | --- | --- |
| （空欄） | A | `185.199.108.153` |
| （空欄） | A | `185.199.109.153` |
| （空欄） | A | `185.199.110.153` |
| （空欄） | A | `185.199.111.153` |
| `www` | CNAME | `ssunchange.github.io` |
| `_github-pages-challenge-ssunchange` | TXT | 手順1で GitHub の画面に出た文字列 |

**手順7のチェックを忘れないこと。** ネームサーバーは、DNS の設定を預けておく先のこと。取得したばかりのドメインは「何もしない初期設定」の預け先になっていて、ここで入れたレコードが効かない。このチェックで、お名前.com の DNS サーバーに切り替わる。設定したのに表示されないときは、まずここを疑う。

#### お名前.com 以外に移したとき

ドメインを別の会社に移したら、その会社の管理画面で上の表と同じレコードを登録する。ホスト名の空欄は、会社によっては `@` と書く。

### 3. リポジトリにドメインを登録する

1. リポジトリの **Settings → Pages** を開く
2. **Custom domain** に `unchange.jp` を入れて **Save** を押す
3. DNS の確認が始まる。緑のチェックが付けば成功

DNS の設定が世界中に行き渡るまで、数分〜最大24時間ほどかかる。失敗表示が出ても、すぐ設定を疑わずに少し待つ。

### 4. HTTPS を有効にする

1. 同じ **Settings → Pages** の **Enforce HTTPS** にチェックを入れる
2. チェックできない（灰色の）ときは、証明書の発行待ち。しばらくしてから再度開く

### うまくいったかの確認

- https://unchange.jp/ と https://www.unchange.jp/ の両方でサイトが表示される
- アドレスバーに鍵マークが付く
- `http://` で開いても `https://` に切り替わる

## 公開前に確認すること

このリポジトリは**公開設定**になっている。`site/` に置いたものは誰でも見られる。

- クライアント名や数字を載せる前に、掲載可否を確認する（[`portfolio/README.md`](../portfolio/README.md) 参照）
- 連絡先は、公開して問題のないものだけを書く
