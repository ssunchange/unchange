# unchange

Webディレクター業務のナレッジと成果物をためていく個人リポジトリ。

案件ごとに散らばりがちな資料・雛形・チェック項目を1か所に集めて、次の案件で使い回せる状態にしておくことが目的。

## 何がどこにあるか

| 場所 | 中身 |
| --- | --- |
| [`docs/templates/`](docs/templates/) | 要件定義書、WBS、議事録などの雛形 |
| [`docs/checklists/`](docs/checklists/) | 公開前チェック、SEO、アクセシビリティなどの確認項目 |
| [`projects/`](projects/) | 案件ごとのフォルダ |
| [`projects/_template/`](projects/_template/) | 新しい案件を始めるときにコピーするひな形 |
| [`portfolio/`](portfolio/) | ディレクターとしての実績。1実績1ファイル |
| [`site/`](site/) | 公開するポートフォリオサイト。GitHub Pages で自動公開される |

## 進め方

**1テーマ = 1ブランチ = 1PR = マージ** を単位にする。

1. 作業用のブランチを作る（本体の `main` は直接いじらない）
2. 変更をコミットしてプッシュする
3. プルリクエスト（PR）を作る。差分を確認する場
4. 問題なければマージして `main` に取り込む

1つのPRに複数のテーマを混ぜない。「テンプレートを1つ足す」「案件を1つ増やす」くらいの粒度で区切ると、あとから履歴をたどりやすい。

思いついたことは Issue に積んでおき、着手するときに PR と紐付ける。

## 新しい案件を始めるとき

`projects/_template/` をコピーして `projects/<案件名>/` を作り、中身を埋める。
